# CLOUD · 2026-11-17 · 개발 회차 08

## 쟁점과 가상 토론

9장 현관의 두 인사와 출발을 점검했다. 인사 도중부터 R을 누른 채로 두면 인사가 끝난 직후 출발 게이지가 차기 시작해 재회의 여운을 건너뛸 수 있었다. 에디터에서의 키보드 검증은 보류하고 기존 출발 규칙을 보완했다.

| 역할 | 제안 | 반론과 응답 |
| --- | --- | --- |
| 서사 디자인 | 현관에서 손녀의 반응을 본 뒤 직접 떠날 때를 정하게 한다. | 레벨 담당은 고정 대기가 재플레이를 늦춘다고 했다. 대기 시간을 두지 않고 새 출발 입력을 기다린다. |
| 레벨·플레이 | 손짓과 빗소리 어느 인사에서든 이미 누른 출발 입력을 먼저 놓게 한다. | 개발 담당은 인사 직후 눌렀을 때까지 막힐 수 있다고 했다. 인사가 끝나는 순간 이미 눌린 경우만 새 홀드를 요구한다. |
| Unity 개발 | 기존 Rest 동작과 홀드 게이지를 재사용한다. | QA는 입력 복구 조건이 화면에 보이지 않으면 막힌 것으로 느낄 수 있다고 했다. 이 상태에만 R을 놓으라는 문구를 보여준다. |
| QA·VR 상호작용 | 두 인사에서 입력 겹침을 검사하고, 출발 홀드 중단·재시도와 장 재진입을 확인한다. | 서사 담당은 산불 도입이 바뀔 수 있다고 했다. 기존 전환과 산불 시작의 물·목표 상태도 같은 회귀에서 확인한다. |

## 결정과 코드

인사가 끝날 때 R을 누르고 있었다면 한 번 놓아야 출발을 시작할 수 있다. 현관에 원하는 만큼 머무른 뒤 R을 새로 길게 눌러 기존 산불 장으로 간다. `CloudJourney.cs`의 Rest 규칙과 `CloudHud.cs`의 안내를 연결했다. `CloudVerify.cs`와 `Tools/verify_story_offline.py`를 갱신했다.

## 실행한 검증

- 실제 C# 스토리 규칙과 `CloudVerify.Story()`를 .NET 8에서 실행했다. Unity 수학 호출 두 종류를 표준 수학으로 대체했다. 기준 코드의 동작을 사용하자 빗소리 인사 뒤 자동 출발 검사에서 실패했다. 수정 후 두 인사에서 기존 홀드 차단, 놓고 다시 누르기, 중단 시 게이지 초기화, 정상 출발, 재진입 초기화를 통과했다.
- 오프라인 스토리와 패키지 검사를 통과했다. 8장 작별부터 9장의 두 인사와 10장 산불, 물 초기화와 순환 엔딩, 97개 에셋 GUID와 연결을 확인했다.
- Unity Chapter Review·Play Mode, 실제 키보드 조준과 완주, PC 빌드, 에디터 재시작 후 저장, 외부 플레이테스트, 실제 모델 교체 및 VR 헤드셋은 미검증이다.
