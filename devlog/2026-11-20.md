# CLOUD · 2026-11-20 · 개발 회차 11

## 쟁점과 가상 토론

직전 회차는 산불 대피의 고도 경계를 안정화했다. 수평 거리는 30을 벗어났다가 조금만 돌아와도 다시 움직여, 경계에서 대피가 짧게 반복될 수 있었다. Unity의 현관 인사와 실제 비행 검사는 보류하고 로드맵 02의 재합류를 이어 보완했다.

| 역할 | 제안 | 반론과 응답 |
| --- | --- | --- |
| 서사 디자인 | 멀어진 구름이 충분히 돌아와야 손녀가 다시 달리게 하자. | 레벨 담당은 멈출 때마다 진행을 잃으면 구출이 반복 노동이 된다고 했다. 물과 이동 진행은 보존한다. |
| 레벨·플레이 | 거리 30을 벗어나면 27 안으로 돌아와야 재개한다. | 개발 담당은 처음부터 27~30에 있는 탐색 비행도 막을 수 있다고 했다. 이미 거리를 벗어나 대기 상태가 된 경우에만 재개 기준을 적용한다. |
| Unity 개발 | 고도 대기와 거리 대기를 함께 관리하고 두 조건이 풀릴 때 이동한다. | QA는 다음 장에서 대기 상태가 남을 수 있다고 했다. 전체 초기화와 장 진입에서 함께 초기화한다. |
| QA·VR 상호작용 | 세 구간에서 거리 이탈 뒤 경계 직하와 충분한 재합류를 비교한다. | 서사 담당은 고도와 거리 안내가 충돌하면 헷갈린다고 했다. 기존 고도 하강 안내를 먼저 보여주고 낮게 내려오면 가까이 오라는 안내를 사용한다. |

## 결정과 실제 변경

`CloudStory.cs`에 재합류 거리를 추가하고 `CloudJourney.cs`에서 거리 대기를 관리한다. 30을 벗어나 멈추면 27 안으로 돌아와야 달리기를 이어간다. 높은 곳에 있다면 기존 하강 조건도 충족해야 한다. 기존 HUD 상태를 사용한다. `CloudVerify.cs`와 `Tools/verify_story_offline.py`에 경계 회귀 검사를 추가했다.

## 실행한 검증

- 실제 C# 스토리 규칙과 `CloudVerify.Story()`를 .NET 8에서 컴파일해 실행했다. Unity 수학 호출 두 종류를 표준 수학으로 대체했다. 기존 규칙에서는 새 경계 직하 대기 검사가 실패했고, 수정본은 세 구간의 경계 대기·재합류·물 보존과 고도·거리 대기 중 장 재진입 초기화를 통과했다.
- 오프라인 스토리 및 패키지 검사 통과. 8장 작별, 9장 두 인사와 R 출발, 10장 각 대피 구간과 기존 순환 엔딩을 검사했다. 97개 에셋 GUID 및 참조 확인.
- Unity Chapter Review·Play Mode, 키보드 실제 조준·비행, PC 빌드, 에디터 재시작 후 저장, 외부 플레이테스트, 실제 아트 교체 및 VR 헤드셋은 미검증이다.
