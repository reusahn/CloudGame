# CLOUD · 2026-11-21 · 개발 회차 12

## 쟁점과 가상 토론

9장 할머니와의 재회 중 E를 누르고 있으면 손녀 인사가 열리자마자 비 인사 진행이 시작될 수 있었다. 손짓에는 새 입력 요구가 있었지만 비 인사에는 없었다. Unity Chapter Review의 키보드 확인은 미검증으로 남기고 9장 두 인사의 의도적 선택을 보완했다.

| 역할 | 제안 | 반론과 응답 |
| --- | --- | --- |
| 서사 디자인 | 손녀에게 건네는 인사를 플레이어가 새 행동으로 고르게 하자. | 레벨 담당은 재회 뒤 고정 대기가 생기면 흐름이 끊긴다고 했다. 이미 누른 비 입력만 놓게 하고 별도 대기 시간은 두지 않는다. |
| 레벨·플레이 | 할머니와의 재회가 끝날 때 Rain이 눌려 있으면 새로 눌러야 비 인사를 시작한다. | 개발 담당은 정상적으로 나중에 누른 입력도 막힐 수 있다고 했다. 재회 완료 순간의 입력 상태만 기억한다. |
| Unity 개발 | 기존 Rain 동작을 유지하고 새 입력 필요 상태를 HUD에 연결한다. | QA는 손짓과 전환하거나 장 재진입할 때 플래그가 남을 수 있다고 했다. 해당 동작을 놓거나 인사를 끝내거나 장을 다시 열면 상태를 초기화한다. |
| QA·VR 상호작용 | 재회 전부터 누른 E, 해제 후 다시 누름, 두 인사와 R 출발을 검사한다. | 서사 담당은 비를 놓는 방법이 전달돼야 한다고 했다. 유효한 조준에서 E를 놓으라는 문구를 표시한다. |

## 결정과 코드

할머니와 손을 잡는 동안부터 E를 계속 누르고 있었다면 한 번 놓고 다시 길게 눌러 손녀에게 비로 인사한다. 기존 손짓 인사와 인사 뒤 새 R 출발을 함께 사용할 수 있다. `CloudJourney.cs`의 입력 상태와 `CloudHud.cs`의 안내를 연결하고 `CloudVerify.cs`, `Tools/verify_story_offline.py`에 회귀 검사를 추가했다.

## 실행한 검증

- 실제 C# 이야기 규칙과 `CloudVerify.Story()`를 .NET 8에서 실행했다. 검사에 쓰인 Unity 수학 호출 두 종류는 표준 수학으로 대체했다. 기존 코드에서는 비를 누른 채 재회를 끝낼 때 인사 단계가 유지돼야 하는 검사가 실패했다.
- 수정 후 기존 Rain 홀드의 자동 인사 차단, 물과 진행 보존, 해제 후 새 비 인사, 손짓 경로, R 출발, 장 재진입 초기화를 확인했다. 오프라인 열 시대·8장 작별·9장 두 인사·10장 산불·순환 엔딩과 패키지 검사도 통과했다. 에셋 GUID 97개와 참조를 확인했다.
- Unity Chapter Review·Play Mode, 실제 키보드 조준·완주, PC 빌드, 에디터 재시작 후 저장, 외부 플레이테스트, 실제 모델 교체 및 VR 헤드셋은 미검증이다.
