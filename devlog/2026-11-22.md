# CLOUD · 2026-11-22 · 개발 회차 13

## 쟁점과 가상 토론

10장 마지막 물방울을 놓는 동작은 F를 놓아도 홀드 진행이 서서히 줄었다. 짧게 여러 번 누르면 진행이 누적돼, 연속 홀드로 마지막 결정을 확인한다는 안내와 차이가 있었다. Unity의 현관 인사·출발 확인은 미검증으로 남기고 산불 이후 마지막 행동의 중단·재시도를 보완했다.

| 역할 | 제안 | 반론과 응답 |
| --- | --- | --- |
| 서사 디자인 | 손녀가 현관에 도착한 뒤 마지막 물방울을 놓는 결정을 연속 홀드로 확인하자. | 레벨 담당은 한번 놓았다고 마지막 장면을 처음부터 반복하면 부담이라고 했다. 마지막 홀드만 취소하고 대피와 물은 보존한다. |
| 레벨·플레이 | 손을 놓거나 유효한 위치를 벗어나면 게이지를 즉시 비우자. | 개발 담당은 기존 할머니와의 손잡기까지 바뀔 수 있다고 했다. 마지막 Release 과제의 홀드 계산에만 적용한다. |
| Unity 개발 | 기존 Reach 동작과 거리·고도 조건을 계속 사용한다. | QA는 이미 누르던 F로 희생이 시작될 수 있다고 했다. 기존 새 Reach 요구도 유지하고 해제 후 새 홀드를 검사한다. |
| QA·VR 상호작용 | 짧은 중단 한 프레임, 재시도, 물 보존과 엔딩을 검사하자. | 서사 담당은 취소 때 효과음이나 대사가 반복될 수 있다고 했다. 기존 게이지와 완료 이벤트만 사용한다. |

## 결정과 코드

`CloudJourney.cs`의 마지막 Release 홀드를 연속 입력으로 계산한다. 중단하면 게이지가 즉시 0이 되고, 같은 현관 위치에서 다시 길게 눌러 최종 비와 순환 엔딩을 시작할 수 있다. `CloudVerify.cs`, `Tools/verify_story_offline.py`에 중단과 재시도 검사를 추가했다.

## 실행한 검증

- 실제 C# 규칙과 `CloudVerify.Story()`를 .NET 8에서 실행했다. 검사에서 사용하는 Unity 수학 두 호출 종류는 표준 수학으로 대체했다. 기존 코드에서는 한 프레임 해제 시 게이지가 0이어야 하는 검사가 실패했다. 수정 후 즉시 취소, 마지막 물 보존, 새 홀드와 기존 희생·순환 엔딩을 통과했다.
- 오프라인 열 시대, 8장 작별, 9장 두 인사와 R 출발, 10장 대피 및 장 재진입, 패키지 검사도 통과했다. 에셋 GUID 97개와 참조를 확인했다.
- Unity Chapter Review·Play Mode, 키보드 실제 조준·완주, PC 빌드, 에디터 재시작 후 저장, 외부 플레이테스트, 실제 아트 교체, VR 헤드셋은 미검증이다.
