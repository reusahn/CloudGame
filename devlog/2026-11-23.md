# CLOUD · 2026-11-23 · 개발 회차 14

## 쟁점과 가상 토론

8장 소녀를 현관까지 데려와 작별한 뒤에는 가만히 있어도 시간이 흘러 9장으로 넘어갔다. 작별 도중 R을 누르고 있었다면 완료 직후 출발까지 이어질 수 있었다. Unity의 현관 조작 검사는 미검증으로 남기고 8장 작별에서 9장 재회로 가는 출발을 보완했다.

| 역할 | 제안 | 반론과 응답 |
| --- | --- | --- |
| 서사 디자인 | 소녀와 작별한 뒤 현관에 머물 시간을 플레이어가 정하게 하자. | 레벨 담당은 고정 대기가 여정 속도를 늦춘다고 했다. 대기 시간을 추가하지 않고 새 R 홀드로 바로 떠날 수 있게 한다. |
| 레벨·플레이 | 작별 완료 전부터 누른 R은 한번 놓고 다시 눌러야 출발하게 한다. | 개발 담당은 안내와 실제 전환이 다르면 막힌다고 느낄 수 있다고 했다. 기존 9장의 출발 안내를 8장 완료 상태에도 연결한다. |
| Unity 개발 | 기존 Rest 동작과 새 입력 필요 상태를 재사용한다. | QA는 소녀를 안내하는 동안의 안개까지 사라질 수 있다고 했다. 작별 완료 뒤의 대기 상태에만 안개 상한을 적용한다. |
| QA·VR 상호작용 | 기존 R 유지, 무입력 대기, 홀드 중단, 새 출발 뒤 재회·산불을 검사한다. | 서사 담당은 중단 때 작별도 취소되면 안 된다고 했다. 출발 게이지만 초기화하고 작별의 완료 상태는 유지한다. |

## 결정과 코드

`CloudJourney.cs`에서 8장 작별 완료 뒤에는 무입력으로 다음 장이 열리지 않게 했다. 작별 중 이미 R을 누르고 있었다면 놓은 뒤 새로 길게 눌러야 9장 재회로 출발한다. `CloudHud.cs`는 같은 출발 안내를 사용한다. `CloudVerify.cs`와 `Tools/verify_story_offline.py`에 검사를 추가했다.

## 실행한 검증

- 실제 C# 규칙과 `CloudVerify.Story()`를 .NET 8에서 실행했다. 검사에 쓰인 Unity 수학 호출 두 종류는 표준 수학으로 대체했다. 기존 코드에서는 작별 전부터 R을 유지하면 현관에 남아 있어야 하는 검사가 실패했다.
- 수정 후 작별 완료 뒤 기존 R 유지 22초 및 별도 무입력 대기 22초에서 현관 유지, 출발 홀드 중단 시 게이지 초기화와 작별 보존, 새 홀드로 9장 전환을 확인했다. 이어 두 인사·R 출발·산불 대피·최종 행동·순환 엔딩까지 검사했다.
- 오프라인 이야기와 패키지 검사 통과. 에셋 GUID 97개 및 참조 확인. Unity Chapter Review·Play Mode, 실제 키보드 조준·완주, PC 빌드, 에디터 재시작 후 저장, 외부 플레이테스트, 실제 아트 교체, VR은 미검증이다.
