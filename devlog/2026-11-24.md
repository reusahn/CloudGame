# CLOUD · 2026-11-24 · 개발 회차 15

## 쟁점과 가상 토론

8장 소녀를 현관까지 안내하는 동안부터 F를 누르고 있으면, 도착 후 작별 홀드가 자동으로 진행될 수 있었다. 직전 회차의 작별 뒤 출발에 이어 작별 자체도 새 행동으로 선택하게 했다. Unity Chapter Review의 현관 검사는 미검증으로 남겼다.

| 역할 | 제안 | 반론과 응답 |
| --- | --- | --- |
| 서사 디자인 | 소녀의 현관 도착을 본 뒤 새로 작별하게 하자. | 레벨 담당은 고정 대기가 흐름을 끊는다고 했다. 새 Reach 입력만 요구하고 대기 시간은 두지 않는다. |
| 레벨·플레이 | 안내가 끝날 때 이미 F를 누르고 있었다면 놓고 다시 누르게 하자. | 개발 담당은 처음부터 누르지 않은 사람도 막힐 수 있다고 했다. 마지막 안내 완료 순간의 입력 상태만 기억한다. |
| Unity 개발 | 기존 Reach 동작과 홀드 게이지를 사용하고 해제 안내를 연결한다. | QA는 장 재진입에 플래그가 남을 수 있다고 했다. 기존 장 초기화에서 함께 지운다. |
| QA·VR 상호작용 | 안내 중 F 유지 → 도착 후 유지 → 해제 → 새 작별 → R 출발을 검사한다. | 서사 담당은 새 입력을 기다릴 때 소녀가 되돌아갈 수 있다고 했다. 현관까지의 이동 완료와 위치를 보존한다. |

## 결정과 검증

`CloudJourney.cs`가 소녀의 마지막 안내 완료 시 Reach 상태를 기억한다. F를 누른 채 도착했다면 놓고 다시 길게 눌러 작별한다. `CloudHud.cs`는 필요한 경우 해제를 안내한다. `CloudVerify.cs`와 `Tools/verify_story_offline.py`에 해당 경로를 추가했다.

- 실제 C# 규칙과 `CloudVerify.Story()`를 .NET 8에서 실행했다. Unity 수학 호출 두 종류는 표준 수학으로 대체했다. 기존 코드에서는 안내 중 누른 F로 작별이 자동 완료되지 않아야 하는 검사가 실패했다.
- 수정 후 소녀의 현관 위치와 완료 상태 보존, 계속 누른 F의 작별 차단, 해제 후 새 작별, 현관 대기와 새 R 출발, 9장 두 인사, 10장 대피·최종 행동·순환을 통과했다.
- 오프라인 이야기·장 재진입·패키지 검사 통과. 에셋 GUID 97개와 참조 확인. Unity Chapter Review·Play Mode, 실제 키보드 조준·완주, PC 빌드, 에디터 재시작 후 저장, 외부 플레이테스트, 실제 아트 교체 및 VR은 미검증이다.
