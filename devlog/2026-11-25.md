# CLOUD · 2026-11-25 · 개발 회차 16

## 쟁점과 가상 토론

소녀가 8장 현관에 도착한 뒤 작별을 고르기 전에 가만히 있으면 안개가 차서 복구 장면이 발생했다. 목적지에 안전하게 도착했는데도 카메라가 높아지고 다시 내려와야 했다. Unity의 현관 키보드 검사는 미검증으로 남기고 도착 후 대기와 동행 구간을 구분했다.

| 역할 | 제안 | 반론과 응답 |
| --- | --- | --- |
| 서사 디자인 | 소녀의 도착 대사를 듣고 작별할 시간을 주자. | 레벨 담당은 숲길의 안개 압박까지 사라지면 여정이 평평해진다고 했다. 현관의 Farewell 과제에만 대기 상한을 적용한다. |
| 레벨·플레이 | 안전한 현관에서는 기다려도 복구 장면으로 이동하지 않게 한다. | 개발 담당은 기다리기만 해도 작별이 끝나면 안 된다고 했다. 기존 새 Reach 입력과 저고도 접근을 그대로 요구한다. |
| Unity 개발 | 기존 Mist 값을 현관 대기에서만 제한한다. | QA는 전후 장 전환이 막힐 수 있다고 했다. 작별 완료 뒤 새 R 홀드가 기존대로 시간 전환을 열게 하고 전체 여정을 검사한다. |
| QA·VR 상호작용 | 22초 무입력 동안 복구 이벤트 자체가 없음을 검사한다. | 서사 담당은 복구 후 돌아온 마지막 화면만 보면 실패를 놓친다고 했다. 모든 프레임에서 Recover 신호를 수집해 검사한다. |

## 결정과 코드

`CloudJourney.cs`에서 소녀가 현관에 도착해 Farewell 과제를 기다리는 동안 안개를 0.43 이하로 제한했다. 숲길 동행과 안개 복구는 기존 규칙을 사용한다. `CloudVerify.cs`와 `Tools/verify_story_offline.py`에 이벤트를 포함한 대기 검사를 추가했다.

## 실행한 검증

- 실제 C# 이야기 규칙과 `CloudVerify.Story()`를 .NET 8에서 실행했다. Unity 수학 호출 두 종류는 표준 수학으로 대체했다. 기존 규칙에서는 현관에서 작별을 고르기 전 대기 중 복구가 없어야 하는 검사가 실패했다.
- 수정 후 무입력 22초 동안 Recover 신호 없음, 현관 도착·소녀 경로 완료·미완료 작별 상태 보존을 확인했다. 이어 새 F 작별, 새 R 출발, 9장 두 인사·출발, 10장 대피·최종 선택과 순환 엔딩을 통과했다.
- 오프라인 이야기·장 재진입·패키지 검사 통과. 에셋 GUID 97개와 참조를 확인했다. Unity Chapter Review·Play Mode, 실제 키보드 조준·완주, PC 빌드, 에디터 재시작 후 저장, 외부 플레이테스트, 실제 아트 교체 및 VR은 미검증이다.
