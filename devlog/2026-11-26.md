# CLOUD · 2026-11-26 · 개발 회차 17

## 쟁점과 가상 토론

8장 현관의 작별에서 홀드를 잠시 끊거나 멀리 날아가도 진행이 서서히 줄어, 다시 가까이 오면 남은 진행을 이어 쓸 수 있었다. Unity 현관 조작은 에디터가 없어 미검증으로 남기고 작별 중단·재시도를 보완했다.

| 역할 | 제안 | 반론과 응답 |
| --- | --- | --- |
| 서사 디자인 | 현관의 작별은 소녀 곁에 머무르며 한 번의 행동으로 마치게 하자. | 레벨 담당은 중단이 소녀 동행을 되돌리면 부담이라고 했다. 작별 홀드만 취소하고 현관 도착은 보존한다. |
| 레벨·플레이 | 멀어지거나 F를 놓으면 작별 게이지를 즉시 비우자. | 개발 담당은 기존 첫 만남과 할머니 재회의 반응도 바뀔 수 있다고 했다. Farewell에만 적용한다. |
| Unity 개발 | 기존 Reach와 거리·고도 조건으로 중단을 판단한다. | QA는 물이 줄거나 도착 상태가 풀릴 수 있다고 했다. 같은 시나리오에서 물과 경로 완료 상태를 함께 검사한다. |
| QA·VR 상호작용 | 부분 홀드 → 멀어짐 → 현관 복귀 → 새 작별·출발을 검사한다. | 서사 담당은 대기 중 안개가 장면을 끊으면 안 된다고 했다. 직전 회차의 현관 대기와 재회·산불 전환도 회귀 검사한다. |

## 결정과 실제 변경

`CloudJourney.cs`에서 Farewell 홀드가 끊기면 즉시 0이 되게 했다. 소녀의 현관 도착과 물은 유지된다. `CloudVerify.cs`와 `Tools/verify_story_offline.py`에 부분 홀드 중 현관을 떠나는 검사와 정상 복귀를 연결했다.

## 실행한 검증

- 실제 C# 이야기 규칙과 `CloudVerify.Story()`를 .NET 8에서 실행했다. 검사에서 사용하는 Unity 수학 호출 두 종류는 표준 수학으로 대체했다. 기존 코드에서는 현관을 떠난 한 프레임에 작별 홀드가 초기화돼야 하는 검사가 실패했다.
- 수정 후 부분 홀드, 위치 이탈 시 홀드 0, 물과 소녀 이동 완료 보존, 새 작별과 R 출발, 9장 두 인사, 10장 대피·마지막 행동·순환 엔딩을 통과했다.
- 오프라인 스토리·장 재진입·패키지 검사 통과. 에셋 GUID 97개와 참조를 확인했다.
- Unity Chapter Review·Play Mode, 실제 키보드 조준·완주, PC 빌드, 에디터 재시작 후 저장, 외부 플레이테스트, 아트 교체와 VR 헤드셋은 미검증이다.
