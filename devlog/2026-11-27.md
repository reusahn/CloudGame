# CLOUD · 2026-11-27 · 개발 회차 18

## 쟁점과 가상 토론

8장 소녀 동행에서 높이 때문에 멈춘 경우와 거리 때문에 멈춘 경우가 같은 상태와 안내를 사용했다. 플레이어가 내려와야 하는지 가까이 가야 하는지 한 번에 두 행동을 요구하는 문장을 보게 됐다. Unity의 현관·재회 검사는 에디터가 없어 미검증으로 남기고 동행 중단 안내를 보완했다.

| 역할 | 제안 | 반론과 응답 |
| --- | --- | --- |
| 서사 디자인 | 멈춘 소녀에게 돌아갈 때 필요한 행동을 분명히 알려주자. | 레벨 담당은 안내가 이동 규칙까지 바꾸면 여정이 달라진다고 했다. 기존 거리·높이 범위와 진행을 유지한다. |
| 레벨·플레이 | 높으면 하강, 낮지만 멀면 접근으로 안내를 구분한다. | 개발 담당은 두 조건이 동시에 나쁘면 안내가 흔들릴 수 있다고 했다. 높이를 먼저 안내하고 내려오면 거리 조건을 안내한다. |
| Unity 개발 | 기존 GuideState에 TooHigh를 뒤에 추가한다. | QA는 기존 상태 번호나 다른 동작이 바뀔 수 있다고 했다. 기존 값은 보존하고 동행 판정과 HUD에만 연결한다. |
| QA·VR 상호작용 | 세 동행 구간에서 먼 위치와 높은 위치의 중단 상태, 물·진행 보존과 복귀를 검사한다. | 서사 담당은 안내가 실제 화면에서도 읽히는지 봐야 한다고 했다. C# 상태 검증과 Unity의 키보드 체감은 구분해 남긴다. |

## 결정과 실제 변경

`CloudStory.cs`에 높은 위치로 인한 중단 상태를 추가했다. `CloudJourney.cs`가 기존 중단 조건에서 이유를 구분하고 `CloudHud.cs`가 하강 또는 접근 문구를 표시한다. `CloudVerify.cs`와 `Tools/verify_story_offline.py`의 세 동행 구간 검사를 갱신했다.

## 실행한 검증

- 실제 C# 이야기 규칙과 `CloudVerify.Story()`를 .NET 8에서 실행했다. 검사에 사용하는 Unity 수학 호출 두 종류는 표준 수학으로 대체했다. 기존 규칙에서는 높은 비행을 별도 상태로 알려야 하는 검사가 실패했다.
- 수정 후 먼 위치와 높은 위치의 중단 구분, 물과 진행 보존, 복귀와 각 지점 도착을 확인했다. 이어 현관 작별·새 출발, 두 재회 인사·새 출발, 산불·최종 행동·순환 엔딩을 통과했다.
- 오프라인 이야기·장 재진입·패키지 검사 통과. 97개 에셋 GUID와 참조 확인. Unity Chapter Review·Play Mode, 실제 키보드 조준·완주, PC 빌드, 에디터 재시작 후 저장, 외부 플레이테스트, 실제 아트 교체와 VR은 미검증이다.
