# CLOUD · 2026-11-28 · 개발 회차 19

## 쟁점과 가상 토론

이전 회차에서 소녀 동행의 중단 이유를 구분했다. 첫 만남·작별·할머니의 손잡기는 가까이 낮게 접근하기 전까지 상황별 입력 안내가 비어 있었다. 키보드만으로 다가가는 플레이어에게 현재 필요한 행동을 알려주도록 보완했다. Unity 실기동 검사는 에디터가 없어 미검증이다.

| 역할 | 제안 | 반론과 응답 |
| --- | --- | --- |
| 서사 디자인 | 인물에게 다가가 손을 내미는 행동을 자연스럽게 안내하자. | 레벨 담당은 안내가 자동으로 상호작용을 끝내면 안 된다고 했다. 기존 Reach와 접근 판정은 유지한다. |
| 레벨·플레이 | 멀면 접근, 가까운데 높으면 하강을 표시한다. | 개발 담당은 판정과 문구 경계가 달라질 수 있다고 했다. 같은 반경과 고도 상수를 사용한다. |
| Unity 개발 | ReachInstruction을 이야기 규칙의 현재 조건에서 계산하고 HUD에 연결한다. | QA는 작별의 새 입력 요구나 재회 중 고정 안내를 잃을 수 있다고 했다. 기존 작별·손잡기 상태도 같은 안내에서 처리한다. |
| QA·VR 상호작용 | 세 Reach 과제에서 먼 위치와 높은 위치의 문구와 진행 차단을 검사한다. | 서사 담당은 글자가 실제 화면에서 읽히는지도 봐야 한다고 했다. 문구 선택 검사와 직접 키보드 체감은 구분해 남긴다. |

## 결정과 실제 변경

`CloudJourney.cs`에서 손잡기·작별 접근 안내를 선택하고 `CloudHud.cs`에 연결했다. 멀면 접근, 가까운데 높으면 하강을 안내하며 유효 위치에서는 기존 F 입력과 해제 안내를 사용한다. `CloudVerify.cs`와 `Tools/verify_story_offline.py`에 검사를 추가했다.

## 실행한 검증

- 실제 C# 규칙과 `CloudVerify.Story()`를 .NET 8에서 실행했다. 검사에서 사용하는 Unity 수학 호출 두 종류는 표준 수학으로 대체했다. 첫 만남·현관 작별·할머니 손잡기에서 먼 위치와 높은 위치의 안내 선택과 실제 상호작용 차단을 확인했다.
- 새 작별 입력·중단·재시도, 현관 대기와 R 출발, 두 재회 인사·R 출발, 산불 대피·최종 선택·순환을 회귀 검사했다. 오프라인 스토리·장 재진입·패키지 검사도 통과했다. 에셋 GUID 97개와 참조를 확인했다.
- Unity Chapter Review·Play Mode, 실제 키보드 조준·완주, PC 빌드, 에디터 재시작 후 저장, 외부 플레이테스트, 실제 아트 교체와 VR은 미검증이다.
